# v0.9.0 變更說明

本版為公開測試版（Prerelease）。更新既有插件時，先完整備份，使用原安裝路徑與原 Chrome 項目的「重新載入」，再於下一場開局前整理 MSA 分頁。

## 與 v0.8 相比改了什麼

| 項目 | v0.8 的情況 | v0.9 的行為 |
| --- | --- | --- |
| 錄製佇列 | 格式永久無效的 Log 持續停在隊首，後續有效手牌也可能無法儲存。 | 格式錯誤原件隔離，可下載救援 JSON；有效觀察繼續儲存。暫時錯誤仍重試。 |
| 介面 | 不同頁面的操作及視覺層級不一致。 | 深色工作台統一四種介面，回顧入口提前，焦點與狀態對比更清楚。 |
| 重複運算 | 狀態更新時可能重做相同 Wasm 計算與公開 Log 摘要。 | 快取相同輸入及摘要；收起小窗時暫停不可見清單更新。 |
| 儲存容量 | 匯入只有寫入量估算，缺少已用容量。 | 顯示實際用量、80%／95% 提醒，匯入確認時重新核對容量。 |
| 自檢 | 大廳未進入對局也視為連線錯誤，未納入牌組引擎狀態。 | 大廳顯示待命；核對分頁版本及本機牌組核心，真正錯誤仍明示。 |
| 戰績草稿 | 保存新牌組後可能重設尚未保存的戰績表單。 | 更新工作資料時保留各段草稿，正式保存後移除草稿提示。 |
| 匯出 | 每次匯出都先要求對局刷新。 | 可選「直接匯出已存資料」，匯出資訊保留未刷新註記。 |

## 新介面與操作

- 小視窗、對局回顧、資料與牌組，以及對戰小窗採一致深色主題。主要動作以青綠色呈現；黃色表示待核對，紅色表示需要處理。
- 容量條使用瀏覽器實際回報的 `storage.local` 用量。超過 80% 提醒備份，超過 95% 明確提示即將用盡。數值不是可錄製場數保證。
- 「資料與牌組」會同步新增的工作資料；尚未保存的戰績草稿會保留。按「保存對局確認」才會正式寫入；關閉頁面前仍需儲存。
- 停在 MSA 大廳時自檢顯示「大廳待命中」，並核對分頁版本與牌組核心；進入對局後才核對本人手牌、儲存及公開 Log。
- 回顧頁勾選「直接匯出已存資料」可以跳過分頁刷新。報告仍標示未刷新；不會把未補齊的資料當成完整。

## 儲存失敗與救援

永久格式錯誤會隔離原件，讓後續有效觀察繼續保存；暫時連線或容量錯誤仍保留待重試。隔離與未保存狀態不算已存快照。

保持原 MSA 分頁開啟，點插件下方「儲存遇到問題？」→「下載未存資料救援 JSON」。檔案包含待存及隔離觀察與其原 game/run 身分，供人工檢查；它不是一般完整備份，也不會自動匯入為已存紀錄。

救援暫存只保留在原分頁記憶體；硬重整、關閉分頁或瀏覽器崩潰仍可能使它遺失。512 筆上限仍存在；滿載時的已拒收觀察不能從佇列補回。容量不足不會自動刪除任何既有記錄。

## 驗證與效能界線

本版保留 v0.8 的資料 schema、權限及同一個 Wasm binary，不需資料庫遷移。合成資料測試與瀏覽器回歸仍不能證明真人整場毫無擷取缺漏。

本機驗證：375 項 JavaScript／Wasm 測試通過；30 項合成瀏覽器錄製回歸通過。另人工檢查新增牌組後戰績草稿保留、保存後草稿提示消失，以及直接匯出的 JSON 具有未刷新標記。Rust 核心未改動。

重複相同輸入的合成 Node v26.12.1 測量（各組暖身 8 次、計時 30 次，取中位數）：

| 人工戰績數／公開事件數 | v0.8 | v0.9 |
| --- | ---: | ---: |
| 1／350 | 3.138 ms | 0.716 ms |
| 100／350 | 8.208 ms | 1.806 ms |
| 500／350 | 27.738 ms | 6.526 ms |

以上只代表快取命中的重複計算，未包含 DOM、磁碟或真人動畫；首次計算及輸入變更仍須運算，不能解讀為實戰幀率或完整捕捉保證。

可執行 `npm test`、`python3 scripts/sync_previews.py --check` 與 `npm run package`。`node scripts/benchmark_projection.cjs [舊版 deck-tracker-core.js 路徑]` 比較重複相同合成輸入的運算時間；此測量不包含真實 DOM、磁碟或對戰動畫，不應當作實戰幀率。

## English

This is the v0.9.0 prerelease. It introduces a consistent dark interface, live storage usage, standby and engine diagnostics, draft-preserving library updates, cached projections, and a saved-data-only export option. Permanent format rejections are isolated instead of blocking later valid observations. Temporary write errors remain queued for retry.

- **UI:** the popup, match review, library, and live panel share a dark workspace, clearer status contrast, and a more accessible review action.
- **Recording:** a permanently invalid Log no longer blocks later valid hand observations. Originals remain isolated for rescue export; temporary failures stay queued for retry.
- **Performance:** identical Wasm inputs and public summaries are cached. Collapsed panels skip invisible list updates. The table above measures repeated synthetic Node inputs with a warm cache, not actual Chrome frame rate.
- **Storage:** actual local usage, 80%/95% reminders, projected import size, and a fresh capacity check before applying an import.
- **Diagnostics:** the lobby is a standby state; page versions and the local deck engine are checked independently.
- **Drafts:** saving a new deck or refreshing library data preserves unsaved match drafts. A match only becomes official after pressing its Save button.
- **Export:** **直接匯出已存資料** exports currently saved data without refreshing MSA, with an explicit audit marker in the export.

Validation includes 375 passing JavaScript/Wasm tests, 30 passing synthetic browser recording checks, and manual browser checks of draft preservation and saved-only JSON export. The Rust core/binary, permissions, and storage schemas are unchanged. Read the [English user guide](user-guide.en.md), [MIT License](../LICENSE), and [contribution guide](../CONTRIBUTING.md).

Keep the original MSA tab open to download the unsaved-observation rescue JSON. Rescue data remains in page memory, is not an ordinary backup, and is not automatically imported as confirmed saved observations. Closing or reloading the tab can lose unsaved data. Storage schemas, permissions, and the packaged Wasm binary remain unchanged. Synthetic checks do not establish complete real-match capture.
