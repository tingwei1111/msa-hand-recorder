# MSA 手牌記錄器使用教學

**繁體中文** · [English](user-guide.en.md)

適用於桌面版 Chrome 與 **v0.8.0 公開測試版（Prerelease）**。工具記錄本人可見手牌與雙方公開 Battle Log，並提供完整牌組卡列、雙方公開使用彙整、對戰小窗、書籤、牌組版本、人工戰績及備份還原。

**尚未完成真人整場對戰的端到端驗證。**第一次使用請先以測試對局人工核對；已存觀察、公開 Log 起尾與完整對戰捕捉是不同概念。

[專案首頁](../README.md) · [版本下載頁](https://github.com/tingwei1111/msa-hand-recorder/releases) · [回報問題／建議](https://github.com/tingwei1111/msa-hand-recorder/issues) · [版本紀錄](../CHANGELOG.md)

## 開始前先讀

這個工具適合想保留自己 MSA 對局、逐回合複盤，或把已收錄資料交給朋友／教練分析的玩家。它觀察頁面上的本人手牌與公開事件，不需要手動截圖，也不會讀取對手隱藏手牌、操作遊戲或自動建議最佳出牌。

| 項目 | 目前狀態 |
| --- | --- |
| 使用環境 | 以桌面版 Google Chrome 與 `https://mobilesuitarena.com/` 為主要使用範圍。其他瀏覽器、行動裝置及不同作業系統組合尚未全面驗證。 |
| 安裝方式 | 從 GitHub Releases 下載安裝 ZIP，再由 Chrome「載入未封裝項目」安裝；目前不是 Chrome 線上應用程式商店安裝。 |
| 介面語言 | v0.8.0 的擴充功能與小窗主要使用繁體中文；英文教學提供按鈕名稱對照，並不表示已有英文介面切換。 |
| 卡片資料語言 | 目前小窗使用官方繁中來源查卡，沒有英文卡文切換選項；實際卡文與圖片語言須看預覽標示，圖片不保證與卡文相同。 |
| 一般使用需求 | 不需安裝 Rust、Node.js、Python 或額外的 WebAssembly 執行環境；安裝包已包含所需核心。 |
| 記錄時間 | 從擴充功能開始觀察且保存成功的內容算起；安裝前或未顯示過的歷史手牌無法補回。 |

第一次使用可依這條流程完成一場測試：

1. **安裝並重新整理 MSA** → 核對 Chrome 顯示的擴充功能版本。
2. **設定本人名稱與手牌位置** → 按「記錄自檢」，確認對局分頁已載入相同版本。
3. **保存牌組版本** → 若要看完整牌組卡列，先準備主牌 50 張；只記手牌與 Log 不以牌組綁定為前提。
4. **進入測試對局並核對保存** → 比較畫面手牌與最近已存快照，再確認公開事件筆數。
5. **確認本場牌組、需要時標記此刻** → 不把未知張數當成零，不把公開使用次數當成剩餘牌庫。
6. **賽後先更新 Log，再匯出與備份** → 確認檔案下載完成後才關閉對局。

可依需要跳到：[安裝與更新](#1-安裝或更新)、[確認有記到](#3-確認真的有記到)、[對戰小窗](#4-對戰側邊小窗)、[匯出](#6-賽後回顧與單場匯出)、[備份還原](#7-備份與匯入還原)、[疑難排解](#11-疑難排解)、[回報與分享](#12-回報問題與分享給其他玩家)。

## 1. 安裝或更新

### 第一次安裝

1. 到 [版本下載頁](https://github.com/tingwei1111/msa-hand-recorder/releases)，打開欲安裝版本的 **Assets**，下載 `msa-hand-recorder-v0.8.0.zip` 這類安裝包。以頁面實際提供的版本為準；`Source code (zip)` 是原始碼下載，不是同一份安裝包。
2. 解壓到會長期保留的固定資料夾。不要直接載入 ZIP，安裝後也不要移動、重新命名或刪除這個資料夾。
3. 在 Chrome 網址列手動輸入 `chrome://extensions`，按 Enter；也可從拼圖圖示選「管理擴充功能」。
4. 開啟右上角的「**開發人員模式**」（Developer mode）。
5. 按「**載入未封裝項目**」（Load unpacked），選解壓後內含 `manifest.json` 的 **`extension` 子資料夾**；不要選 ZIP 或最外層版本資料夾。
6. 確認列表出現「MSA 手牌記錄器」及預期版本，且擴充功能已啟用。在拼圖選單釘選它，方便開啟小視窗。
7. **開局前重新整理 MSA 分頁**，再依第 2 節進行設定與自檢。只重新載入擴充功能，不會讓原本已開啟的 MSA 分頁自動換成新程式。

```text
msa-hand-recorder-v0.8.0/
├── README.md
├── docs/
└── extension/       ← Chrome 載入這個資料夾
    ├── manifest.json
    ├── wasm/        ← 連同其他檔案完整保留
    └── …
```

官方 Chrome 安裝步驟可參考 [Load an unpacked extension](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)。GitHub 網頁更新或發佈新版本，不會自動更新已載入的未封裝擴充功能。

### 找到目前安裝的資料夾

更新前先找原位置，避免把新版裝成另一個擴充功能：

1. 手動開啟 `chrome://extensions`，找到「**MSA 手牌記錄器**」。若有多個 Chrome 使用者設定檔，先確認這是平常玩 MSA 的那一個。
2. 按「**詳細資料**」（Details）。
3. 一直往下捲到接近最底部，在「**移除擴充功能**」上方找到「**來源**」（Source）區塊。
4. 找到「**載入來源：**」（Loaded from:），其後的路徑就是目前使用的資料夾。macOS 可按 `⌘F`、Windows 可按 `Ctrl+F` 搜尋「載入來源」或 `Loaded from`。
5. 路徑可點擊，會開啟系統檔案管理員顯示該資料夾。先記下路徑與 Chrome 顯示的擴充功能 ID，供更新後核對。

若完全沒有「載入來源」這行，先確認是否選對擴充功能，並在 [問題回報](https://github.com/tingwei1111/msa-hand-recorder/issues) 提供經檢查的畫面與版本。不要為了找路徑先移除擴充功能。

### 更新既有安裝並保留資料

1. 等目前對局結束；先保留對局分頁，完成 Log 更新與保存核對。
2. 開啟「**資料與牌組**」，按「**下載完整備份**」，到 Chrome 下載項目確認 JSON 已保存。較舊版本若沒有完整備份功能，先下載能取得的各段原始 JSON。
3. 將新版 ZIP 解壓到暫存位置，先確認內有完整的 `extension` 與 `wasm` 檔案。
4. 備份原來的程式資料夾，再把新版 `extension` 內的檔案與子資料夾更新到**原來同一個 `extension` 資料夾**。不要只複製 `manifest.json`，也不要再按「載入未封裝項目」新增另一份安裝。
5. 回到 `chrome://extensions`，在原本那張「MSA 手牌記錄器」卡片按圓形箭頭「**重新載入**」（Reload）。不要按「移除」。
6. 核對版本已更新、擴充功能 ID 仍是原來那個，並確認舊對局仍可從小視窗或管理頁選取。
7. 在下一場開局前重新整理 MSA 分頁，再按「記錄自檢」確認分頁版本一致。資料沒有出現或載入出錯時，先保留原始備份與舊程式副本，再回報。

本版沿用既有 JSON／獨立 HTML 備份格式，不需手動改 schema 或轉換資料庫。Chrome 資料依使用者設定檔與擴充功能 ID 分開；換設定檔、換安裝路徑或解除安裝後，不能假定會自動看到原資料。

官方單卡查詢沿用 `www.gundam-gcg.com` 網站權限。若從較舊版本更新後，Chrome 要求確認此權限，請核對用途與網域；記錄器仍不讀 MSA 私有後端。Rust／Wasm 核心隨安裝包提供，不從 CDN 下載。

### v0.8.0 牌組核心載入狀態

v0.8.0 的牌組驗證、手牌分類、雙方公開使用彙整、Token 分列與版本戰績由 Rust 編譯的 WebAssembly 計算；畫面觀察、儲存與匯出仍沿用原流程。這次改寫以行為相容為目標，不承諾比舊 JavaScript 更快。

- **「牌組核心載入中」：**等待本機核心完成載入，暫時不能綁定牌組；可切到手牌或公開事件查看已存資料。
- **「牌組核心無法使用」：**先保留對局並備份，確認新版程式完整、Chrome 已重新載入擴充功能、MSA 分頁已重新整理。不要把此錯誤解讀為空手、零次出牌或沒有記錄。
- **手牌與 Battle Log：**核心載入／失敗不會要求清除既有記錄，原有手牌與公開事件記錄流程仍可運作；仍須核對儲存與待存狀態。

沒有隱藏的舊 JavaScript 牌組計算備援。完整技術與重建方式見 [Rust／Wasm 說明](Rust-Wasm.md)。

## 2. 開局前設定與自檢

點開擴充功能，確認「自動記錄」已開。開關代表啟用，**不代表資料已保存成功**。

展開「記錄設定」：

- **我的玩家名稱：**可填自己的 MSA 名稱，協助鎖定本人。
- **我的手牌位置：**先使用「自動：下方玩家手牌」。只有確定本人手牌位置時才手動指定，不要把旁觀畫面的其他玩家指定為本人。
- **自動收錄 Battle Log：**建議保持開啟；修改後按「儲存設定」。

自動 Log 收錄會在開局、結束的安全閒置時機嘗試短暫顯示 Log，讀取後恢復原狀。原本已開啟時直接讀取；輸入中、有遊戲對話框或處於不宜打斷的動作階段時，可能延後或無法刷新。

關閉「自動收錄 Battle Log」只停用開局與結束的自動顯示。明確按「更新 Log」或匯出時，仍可在安全條件下要求讀取。

### 按「記錄自檢」

先切到要檢查的 MSA 對局分頁，再開擴充功能按「**記錄自檢**」，展開「目前分頁自檢結果」。核對：

1. 擴充功能與對局分頁載入的版本是否一致。
2. 設定是否載入、記錄是否啟用、本人名稱是否確認。
3. 本段已存手牌、待存筆數、最近儲存錯誤與辨識品質。
4. 已存公開事件及 Log 起尾狀態。

自檢沒有替你實際數手牌，也不能證明未曾漏掉動畫中的瞬間。版本不符時，在合適時機重新整理 MSA 頁面後再檢查。

若要使用完整牌組追蹤，開局前先到「資料與牌組」保存完整的牌組版本；第 8 節有牌表格式與保存方式。小窗會在本人手牌已成功保存後，讓你確認本場使用哪個版本。

## 3. 確認真的有記到

第一次發牌、抽牌與出牌後，各做一次人工核對：

1. 對局與玩家是本人正在玩的這場。
2. 數清畫面上的手牌，再比對已存卡號、已辨識張數、預期總數與未辨識張數。
3. 快照內容、觀察時間或筆數確實更新；不要只看啟用開關。
4. 公開事件筆數與回合來源合理。
5. 打開「開啟對局回顧」，確認剛才的卡號、數量及觀察時間能從已存資料中讀回；下載測試報告，確認檔案可開啟。

例如畫面有 4 張手牌，但只辨識出 3 張卡號時，請核對未知／部分辨識提示；不要把已辨識 3 張當成全部手牌。快照筆數暫時不變，也可能只是同一回合沒有可保存的變化；應連同觀察時間、卡號、回合與待存狀態一起判斷。

若尚未讀到公開事件，保持對局開著，按「更新 Log」；也可自行開啟 Battle Log。使用遊戲的 `L` 快捷鍵前，先移開聊天或表單的輸入焦點。

儘早讀到 Log 有助於校準後續回合。若直到賽後才第一次讀取，之前未校準的手牌仍保留為「觀察回合」，不會假裝已精確回填。

擴充功能小視窗可以關閉；只要對局分頁正常運作，記錄器仍會觀察。背景節流、瀏覽器休眠、關頁或動畫可能造成缺漏。重新整理、變更玩家設定或暫停後恢復可能建立新段落，原段落仍保留。

## 4. 對戰側邊小窗

在 MSA 對局頁點角落的「**對戰小窗**」展開，或從擴充功能按「**顯示對戰側邊小窗 ↗**」。這是頁面內的小窗，切換到其他程式後不會永遠置頂，也不會替你出牌或選目標。

![v0.7 完整牌組追蹤合成示範](images/deck-tracker-v0.7.jpg)

*畫面使用合成示範資料，不是真實對戰；此圖呈現 v0.7 介面，v0.8 保留相同主要操作。*

### 分頁與顯示設定

- **牌組：**查看本場凍結主牌表、已存手牌張數、公開使用次數，以及同版本人工戰績；下方分列雙方公開使用與 Token 生成。
- **手牌：**查看最近已存的本人手牌、資源與相鄰觀察差值。
- **公開事件：**查看最近公開出牌與 Token 生成；最多 20 筆，最新在上。
- **全部：**同時查看牌組、手牌與公開事件。
- **顯示設定：**可調寬度、字級，以及「自由移動／貼左側／貼右側」。窄視窗會限制可用寬度。

拖住標題可移動；以 `Tab` 聚焦標題後，方向鍵每次移動 10 像素，`Home` 重設位置。拖曳或方向鍵移動會切回自由位置。按「收合」，或在小窗內按 `Esc`，即可保留角落入口並收起內容。

分頁、寬度、字級、位置與展開偏好獨立保存。收合不等於暫停記錄，調整顯示也不會改寫對局資料。遊戲對話框出現時，小窗會暫時隱藏讓路，不會替你關閉遊戲對話框。

### 在小窗選擇本場牌組

1. 先從「資料與牌組」保存牌組版本：主牌 50 張，資源與 Token 另列。小窗中的「管理牌組」也可開啟管理入口。
2. 回到 MSA 對局，確認本人名稱及本段手牌已成功存入。沒有已存本人手牌時，先核對記錄設定與儲存狀態。
3. 開啟「**牌組**」分頁，展開「**選擇本場牌組**」，在「**選擇已保存的牌組版本**」挑選實際使用的版本。
4. 核對顯示的本場玩家，按「**確認綁定本場牌組**」。這次確認表示本人在此局使用該牌表，不會自動確認勝負。
5. 確認小窗顯示牌組名稱、版本、主牌 50 張及完整卡列。版本內容會凍結，日後另存改牌版本不會改寫本場。

已綁定時可展開「重新選擇本場牌組」。同一版本再次確認不重複改寫；本場結果若已人工確認，更換凍結牌組須到「資料與牌組」核對後修改。切換對局、玩家或記錄段落後，請重新確認操作內容，不沿用舊場草稿。

### 三種數量與公開卡號彙整

| 欄位 | 解讀方式 |
| --- | --- |
| 牌表 | 本場凍結主牌表的同卡張數；格式核對後主牌合計 50 張。 |
| 手牌 `n` | 最近已存且張數可核對的完整本人觀察。未見該卡時可顯示 `0`，不代表它已從牌庫耗盡。 |
| 手牌 `≥n` | 部分辨識中至少看到的張數。未辨識的部分仍未知。 |
| 手牌 `?` | 目前沒有可核對的該卡手牌張數；不能當作 `0`。 |
| 公開使用 | 已收錄且能辨認主要卡號的公開使用累計次數。重複使用同卡會再次計數。 |

卡列依牌表合併同卡號。本人已存手牌或公開使用出現牌表外卡號時會提示，這些觀察不加進主牌 50 張，也不自動改寫牌表。已知卡名可一併顯示；沒有卡名時保留卡號，不猜測別張卡片。

展開「**本人公開使用**」「**對手公開使用**」可看按卡號彙整的紀錄；只有已確認玩家來源的動作才歸到對手。玩家或卡號不明時留在「**待核對的公開使用**」，Token 放在「**Token 生成（不計手牌出牌）**」。彙整採全部已接受的公開事件；「公開事件」分頁仍保留最近 20 筆及原文入口。

**公開使用不是手牌消耗或實體卡數。**回手再使用會增加次數，因此它可能超過牌表同卡張數。部署來源區域、Shield、洗回及其他區域資訊不完整時，不能用「牌表 − 手牌 − 公開使用」推算精確剩餘牌庫，也不能因一張卡使用多次就把它標成耗盡。

「**數量與來源說明**」可核對手牌來源、公開 Log 涵蓋及待核對項目。卡列由已存牌表、快照與公開事件投影而成；原始快照和 Log 持續保留，沒有額外補造抽牌、出牌或區域移動事件。

### 同版本人工戰績

綁定後，小窗頂部會顯示**目前所綁同一版本、本人**的人工戰績、樣本數及總勝率。相同對局多段記錄只算一次；未確認結果不進分母，樣本為零時顯示未知。本人投降計入負場，和局計入總勝率分母。

這項統計沿用第 8 節的賽後人工確認；它不會因開局綁定牌組、出現結束畫面或收錄完整 Log 就自動判勝負。不同改牌版本分開計算，管理頁可進一步按版本與先後手篩選。

### 已存手牌與差值

手牌只來自**當前段落、確認玩家相符、成功儲存的最近快照**。尚在待存的狀態不提前顯示為已存；新段落尚無快照時，不借用上一段手牌。

若目前畫面待辨識，但上一筆已存快照完整，小窗會保留舊快照並提示。請看觀察時間，不要把它當作此刻完整手牌。身分未確認時，不顯示本人手牌。

只有同來源段落、相鄰且完整的快照才比較增減。`+1`／`−1` 表示卡號數量變化；**不代表已確認抽牌、使用、棄牌或回手**。跨段落、未知或部分辨識不推算差值，也不據此計算精確剩餘牌庫。

資源分列等級、一般可用、EX 可用及合計；缺少欄位保留未知。Token 標為生成，不當作從手牌出牌；其他部署來源未明時，也不直接算作手牌消耗。

### 查官方卡圖與卡文

在小窗將滑鼠停留於卡號、用鍵盤聚焦卡號，或點擊卡號開啟預覽。核對卡名、卡號、卡文語言、圖片語言、擷取時間與「**官方來源**」連結。

目前對戰小窗固定查詢官方繁中來源，沒有英文卡文切換選項；英文教學不會自動切換查卡語言。實際圖片可能為日文，並不保證與卡文語言一致。找不到卡片、圖片載入失敗或網路中斷時會顯示原因；工具不會用其他卡的資料補上。查卡也不是禁限卡或賽制合法性驗證。

資料按單一卡號從 `www.gundam-gcg.com` 取得，使用不附帶憑證與 referrer 的請求。只有短期記憶體快取，不占對局的本機儲存容量；官方卡文與圖片不預先整批包進 GitHub 或安裝檔。

完整牌組卡列的卡號也沿用相同預覽；滑過、聚焦或點擊時查詢該張卡，不會為整份牌組預先批次下載官方卡圖。

### 更新 Log 與異常提醒

按「**更新 Log**」後，工具先等候約 0.9 秒，讓點擊結束，再檢查能否安全讀取。輸入、其他對話框或攻擊／選目標階段仍受保護；無法刷新會顯示原因，已存資料保留。

遇到寫入失敗、可見變化尚未確認保存、已看見本人手牌卻沒有本段快照，或賽後 Log 起尾仍待確認時，小窗可顯示「記錄需檢查」提醒。按「**知道了**」只收起這次提醒，**不代表錯誤修復或缺口被補回**。賽後提示也可按「收起提醒」收合。

## 5. 標記此刻與回顧筆記

對戰中按「**標記此刻**」，核對編輯區顯示的來源快照，填寫短筆記或標籤，再按「**儲存書籤**」。書籤固定在按下標記時的已存快照；編輯期間又抽到牌，不會把錨點移到新快照。

只有身分與來源相符的已存手牌才能標記。對局或玩家改變時，應重新開啟標記，不把文字存到另一場。

賽後在回顧頁：

- 在指定快照按「**新增筆記**」新增註記。
- 從本場筆記列表回到原快照，重新核對當時手牌、回合來源與時間。
- 可修改標籤與文字；原始對局、來源段落、快照及觀察錨點保持不變。
- 刪除採可恢復方式；需要時在已刪除筆記中恢復。刪除註記不會刪掉對局快照。

筆記另存本機資料，完整備份會包含它們。單場 JSON／HTML 的匯出資訊也可攜帶這場相關的筆記、人工確認與牌組版本；原始對局 JSON 不被改寫為筆記內容。這不表示 Markdown／CSV 都含同一份工作資料，整體備份請用「下載完整備份」。

## 6. 賽後回顧與單場匯出

1. 先保留 MSA 對局分頁，核對賽後提醒、待存資料與公開 Log。
2. 按小窗「**對局回顧**」，或從擴充功能選對局後按「**開啟對局回顧**」。
3. 保留「合併同對局的相容記錄段落」；它只合併同場、同一確認玩家的手牌及相容公開 Log，不覆寫原段落。
4. 核對 Log 開局／結束、未校準回合、公開紀錄缺口及手牌缺口。
5. 選「獨立 HTML 報告」，按「匯出 HTML 報告」。工具嘗試刷新對應分頁、等待保存，再重讀本機資料產生報告。
6. 查看匯出前刷新結果，到 Chrome 下載項目確認檔案保存後，再關閉對局分頁。

分頁關閉、刷新逾時或安全條件不符時，仍可匯出既有資料，但報告會保留原因。小窗尚無安全的本段回顧來源時，按鈕停用，不會改開另一場。

回顧頁可搜尋回合、玩家、卡名及卡號，使用上一／下一回合、左側回合索引與手牌／出牌／公開事件捷徑。下載包含選取範圍的全部已存資料，不受目前搜尋條件限制。

| 要做的事 | 建議格式 |
| --- | --- |
| 閱讀或分享單場已收錄內容 | 合併相容段落後匯出獨立 HTML，可離線閱讀。 |
| 交給文字分析或保留原始欄位 | Markdown 或 JSON；JSON 保留未知欄位與來源記錄。 |
| 試算表整理 | 手牌 CSV、公開事件 CSV 或整合 CSV；不要把擷取時間當事件時間。 |
| 備份所有對局、筆記與牌組戰績 | 「資料與牌組」→「下載完整備份」。 |

獨立 HTML 不需要外部字型或官方卡圖才能閱讀；內嵌 `msa-record-data` 原始 JSON 與 `msa-export-info` 匯出資訊。管理頁匯入時只解析資料，不執行 HTML 裡的程式。

## 7. 備份與匯入還原

從擴充功能的「**資料與牌組**」、小窗的「資料與牌組 · 備份與還原」，或回顧頁的「資料與牌組管理」開啟管理頁。

![v0.6 本機資料庫合成示範](images/library-v0.6.jpg)

### 下載完整備份

按「**下載完整備份**」。內容包含目前本機的對局、筆記、牌組版本、人工戰績與匯入原件；保留未知欄位。錄製設定、分頁狀態、小窗位置不包含在還原白名單內。

「已產生並開始下載」不等於檔案已落到硬碟；請到 Chrome 下載項目確認。換電腦、換 Chrome 使用者設定檔或移除擴充功能前，先保留這份檔案。

### 預覽後確認匯入

1. 選擇批次備份 JSON、單場 JSON，或本工具的獨立 HTML；單檔上限 20 MiB。
2. 核對來源、資料筆數、對局段數、新增／衝突／相同跳過數量及估計寫入量。**此時尚未寫入。**
3. 閱讀每筆的處理方式，再按「**確認匯入這些資料**」。資料若在預覽後改變，會要求重新核對預覽。
4. 依結果核對成功保存、跳過及未完成項目。全部相同時會提示無需再匯入。

衝突處理會保留本機內容：對局另存新 ID，但保留原 game／玩家身分；牌組版本衝突另存版本並連結相應匯入資料。筆記、人工確認等衝突原件會封存，並可從「**匯入原件與衝突副本**」按「**下載原始資料**」取回。原始副本不等於自動覆蓋目前筆記或戰績。

同檔重匯會跳過相同資料或已有的相同匯入副本；不同段落及合法重複公開事件仍保留，不會以事件文字相同為理由刪除。

### 容量不足或只完成部分

估計寫入量包含還原原件，可能比原始對局資料大；它不是剩餘可用容量。寫入採逐筆核對，不是原子交易，容量不足或中斷可能只完成部分。

請保留原始檔，查看「已核對保存」與未完成鍵，必要時下載已封存原件。處理容量或錯誤後再重新預覽、確認；不要因畫面有部分新增資料就當作完整還原，也不要先解除安裝。

## 8. 牌組版本與個人戰績

### 建立不可覆寫的牌組版本

在「保存每一次改牌」填名稱與主牌組，資源及 Token 放在各自欄位。支援：

```text
4xGD01-001
4 GD01-002
GD01-003x4
```

上面只示範格式，不是一份完整牌表。工具合併同卡號後檢查主牌 50 張與同卡號上限 4 張；資源／Token 不計入主牌。資源與 Token 分欄是使用者指定的資料，**沒有額外驗證卡片類型、存在與否、顏色限制、禁限卡或當期賽制合法性**。

格式符合後按「**保存為牌組版本**」。從既有版本開始修改再保存，會產生新版本；相同內容已有版本時保留原版，不修改已綁定的對局。需要另一副牌時用「清空並建立新牌組」。

牌組保存後，可依第 4 節在對戰小窗確認本場綁定，再於賽後到管理頁補上先後手與結果。手牌片段不會被自動當作完整牌表。

### 對局綁定與人工確認

在「替對局補上你的確認」：

1. 選本機對局段落，核對來源與本人名稱。
2. 勾選「我確認這是本人在這場對局使用的名稱」。
3. 選當時使用的牌組版本；儲存時會凍結完整版本。
4. 確認先後手與本人結果，勾選結果確認後按「**保存對局確認**」。不確定的欄位保留「尚未確認」。

對手投降請選「勝（含對手投降）」；本人投降選「本人投降（計負）」。Log 出現結束標記不會自動判定誰獲勝。

同一 game／確認玩家只算一場，即使有多個記錄段落。從另一段更新同場確認，不會增加場數。保存的凍結牌表不隨後續改牌改變；手牌不完整時也不拿它反推精確牌庫。

### 勝率與分母

「看得見樣本數的戰績」可按牌組版本與先後手篩選，並列出確認與未確認場數：

- **總勝率：**勝場 ÷ 已確認的勝、負、和局、本人投降場次。
- **決勝勝率：**勝場 ÷ 已確認的勝、負、本人投降場次，排除和局。
- **本人投降：**計入負場，另列投降樣本數。
- **尚未確認：**不列入兩種勝率分母；樣本為零時顯示未知，不顯示虛構的 0% 勝率。

這是本機人工確認樣本，不代表所有 MSA 對局，也不自動推論牌組強度。

## 9. 讀懂資料標示

| 標示 | 如何解讀 |
| --- | --- |
| 最早／最晚觀察 | 回合中第一次及最後一次已存觀察，不保證是真正回合開始／結束手牌。 |
| 完整辨識 | 此次快照符合辨識條件；初次使用仍要人工核對。 |
| 部分／無法辨識 | 已知卡號不等於全部手牌；沒有卡號不代表空手。 |
| Log 確認／校準 | 回合資訊來自當時可見公開 Log。 |
| 推計回合 | 由之前資訊推進，這次沒有直接從 Log 確認。 |
| 觀察回合 | 工具自己的序號，尚未對齊遊戲絕對回合；不同段落不任意接起。 |
| 快照差值 | 同來源相鄰完整觀察的數量差，增減原因未知。 |
| 卡列「牌表」 | 本場凍結版本的張數，不隨本局使用次數扣減。 |
| 卡列手牌 `≥`／`?` | 分別表示已辨識下限與未知，不把部分辨識補成確定張數。 |
| 卡列「公開使用」 | 已收錄的使用次數，可超過牌表張數，不等於手牌消耗或剩餘牌庫。 |
| 牌表外觀察 | 本人手牌或公開使用出現未列在所綁主牌表的卡號，需核對版本與來源。 |
| 公開 Log 已見起尾 | 已存公開事件涵蓋開局及結束，不代表手牌全程完整或伺服器保證。 |
| 手牌擷取缺口 | 已知待存或緩衝缺口；後來的完整 Log 不能補回。 |
| 首次擷取時間 | 工具第一次讀到事件的時間，不是事件實際發生時間。 |
| 知道了／收起提醒 | 收起提示，不是修復、補記或完整性確認。 |

中途安裝、暫停、關閉分頁、尚未開始記錄前的歷史手牌，以及未被觀察到的動畫瞬間，都不能事後還原。舊記錄缺少 EX 時保留未知，不能補成 0。

## 10. 資料與隱私

資料保存在目前 Chrome 使用者設定檔，沒有自動雲端同步或備份。對局、筆記、人工戰績與匯出操作在本機處理，不自動上傳對局。

記錄器只讀 MSA 已顯示的 DOM，不讀 cookie、不攔截 WebSocket、不請求 MSA 私有 API 或讀對手隱藏手牌，也不自動出牌或傳訊息。

查官方卡片時會向 `www.gundam-gcg.com` 發出單卡公開請求，使用 `credentials: omit`、`no-referrer`，不附帶對局記錄。卡文／圖片的來源與語言會顯示；短期記憶體快取不寫進對局儲存。詳見[卡片資料來源](card-sources.md)。

**備份或報告可能包含本人手牌、玩家名稱、筆記、牌組與戰績。**分享前請檢查；資料在本機不表示匯出檔已匿名化。

## 11. 疑難排解

| 情況 | 可以先做的檢查 |
| --- | --- |
| Chrome 找不到 manifest | 先解壓，再選含 `manifest.json` 的 `extension` 子資料夾；不要選 ZIP 或最外層版本資料夾。 |
| 看不到英文介面切換 | v0.8.0 主要介面仍為繁中；請使用 [English user guide](user-guide.en.md) 的繁中按鈕對照。英文文件不會改變介面語言。 |
| 找不到安裝資料夾 | 到擴充功能「詳細資料」最底部，找「來源」區塊中的「載入來源：」；點路徑開啟檔案管理員，見第 1 節。 |
| 下載新版後版本仍舊 | 下載不等於安裝。更新原資料夾、重新載入原擴充功能，再重新整理 MSA 並自檢。 |
| 更新後看不到舊對局 | 先核對 Chrome 設定檔、原擴充功能 ID 與原安裝路徑；不要急著清除資料。保留原 JSON 備份，按第 7 節預覽還原。 |
| 牌組核心一直載入中或無法使用 | 核對完整 `extension/wasm` 檔案、新版載入及分頁版本。先備份能讀取的資料；手牌／公開 Log 儲存狀態須另行核對。 |
| 找不到小窗或新版功能 | 在合適時機重新整理 MSA 頁面，再按「記錄自檢」核對版本。遊戲對話框開啟時小窗會退讓。 |
| 小窗手牌比畫面晚 | 看已存時間、待存筆數與辨識／儲存錯誤；它不提前顯示尚未保存的狀態。 |
| 牌組清單沒有可選版本 | 先到「資料與牌組」保存符合主牌 50 張與同卡號上限的版本；資源／Token 分欄。 |
| 無法綁定本場牌組 | 核對本人名稱、本段已存手牌、對局及分頁來源；對局或玩家改變後重新操作。 |
| 已確認結果後小窗不能換版 | 到「資料與牌組」核對該場人工確認，再修改所綁凍結版本。 |
| 公開使用次數超過牌表數量 | 次數會包含同卡再次使用，不限於實體卡張數；核對原始公開 Log，不據此計算剩餘牌庫。 |
| 牌組卡列只有卡號或顯示 `?` | 卡名與手牌數未取得時會保留未知；核對觀察來源，單卡預覽可查官方資料。 |
| 小窗戰績與另一版本不同 | 小窗只統計目前綁定的同版本、本人已確認結果；新舊版本分開，未確認結果不列分母。 |
| 健康提醒一直出現 | 核對原始原因；「知道了」不會修復儲存錯誤。先備份能讀取的資料，不要直接解除安裝。 |
| 只有手牌、Log 為零 | 保持對局頁開啟，安全時按「更新 Log」或自行開啟 Log，再看筆數。 |
| 更新 Log 或匯出刷新失敗 | 完成輸入或遊戲操作、關閉不需要的對話框後再試；既有資料可匯出，但不能當作補齊。 |
| 卡文或圖片沒有載入 | 看來源／語言及錯誤提示，確認官方網站權限與網路；不影響既有對局資料。 |
| 無法標記快照 | 先確認本人身分且本段已有保存的手牌。切局後重新標記，不沿用舊編輯錨點。 |
| 筆記找不到來源快照 | 檢查對局與合併段落範圍；保留備份與來源 ID，不手動改成另一場。 |
| 匯入沒有開始寫入 | 選檔只會預覽；有新增資料時需按「確認匯入這些資料」。全部相同則無需重匯。 |
| 匯入只完成部分 | 保留原始檔，核對已保存／未完成項目與容量，再重新預覽。 |
| 格式過大／不安全／不支援 | 僅支援本工具資料格式與白名單資料鍵；20 MiB 以上請分批，不自行刪掉未知欄位冒充成功。 |
| 牌組不能保存 | 核對格式、主牌 50 張與同卡號上限 4 張，將資源／Token 移到分欄。 |
| 戰績數量比記錄段少 | 同場／同玩家只計一次，未確認結果不進勝率分母；檢查篩選條件。 |
| 下載後找不到檔案 | 到 Chrome 下載項目核對。「開始下載」不等於已保存。 |

### 常見使用問題

**一定要先匯入牌組，才能記錄嗎？**

不需要。手牌與公開 Battle Log 的錄製不以牌組綁定為前提。保存並確認本場牌組後，才會顯示完整凍結牌表卡列及該版本人工戰績。

**能看對手的手牌、重新找回以前每回合的手牌嗎？**

不能。對手區只有已收錄的公開使用，不是隱藏手牌。舊對局或中途安裝可以收錄當時可見的公開 Log，但安裝前、未觀察到或保存失敗的手牌無法事後還原。

**可以自動判斷勝負、剩餘牌庫，或告訴我最佳出牌嗎？**

目前沒有這些功能。結果與先後手由使用者確認；公開使用是次數，不能當作實體卡張數；手牌增減原因也未被確認。報告提供賽後分析資料，不直接判定最佳出牌。

**能離線使用嗎？**

已下載的獨立 HTML 報告可離線閱讀；當下遊戲仍依 MSA 網站運作。官方卡文／圖片預覽需連網，沒有把整套官方卡圖打包離線提供。

**可以同步到另一台電腦或另一個 Chrome 設定檔嗎？**

沒有自動同步。先在原環境下載完整備份，再在另一個環境安裝工具、預覽並確認匯入。錄製設定與小窗偏好不會隨匯入覆寫，需重新設定。若匯入只完成部分，請保留原檔並核對結果。

**可以用 Edge、Brave、Firefox、Safari 或手機嗎？**

目前教學與安裝流程以桌面版 Chrome 為主。其他瀏覽器／裝置未全面驗證，不能因支援部分 Chrome 擴充功能就視為本工具已通過相容性測試。

## 12. 回報問題與分享給其他玩家

### 提出可重現的問題

在 [GitHub Issues](https://github.com/tingwei1111/msa-hand-recorder/issues) 回報錯誤或功能建議；繁體中文與英文皆可。建議提供：

- 擴充功能版本，以及 Chrome 版本與作業系統。
- 從哪個頁面開始、按了哪些按鈕、發生問題前後的操作步驟。
- 預期結果與實際結果，例如「畫面 4 張手牌、最近已存仍 3 張」，而不是只寫「壞了」。
- 「記錄自檢」中與問題有關的版本、待存筆數、錯誤與品質資訊。
- 問題是否能在合成預覽或測試對局重現，以及是否只發生在特定對局／重新整理後。

先檢查截圖、JSON、HTML、玩家名稱、筆記及牌組中有沒有不想公開的內容。不要上傳 Cookie、登入資訊、完整 Chrome 使用者設定檔、私人路徑或未經同意的真實對局。原始備份請自行保留；公開問題盡量使用合成範例或不含私人內容的最小重現資料。

若要提交程式修正，請附重現方式、改動目的與相應驗證；開發環境與合成預覽見 [專案首頁](../README.md) 和 [Rust／Wasm 說明](Rust-Wasm.md)。不確定紀錄是否完整時，請分別說明已存快照、公開 Log 涵蓋及尚未確認的部分；自動測試和合成預覽不能代替真人整場驗證。
